# Shadowrocket 两步导入记录

## 最终支持方式

Shadowrocket 把首页节点订阅和配置页原生配置保存为两个独立对象。单独导入任何一个都只能得到一半能力，因此页面必须提供严格有序的两步入口：

1. **首页节点订阅**：具名 HTTPS `.yaml` 地址；一键导入使用 `shadowrocket://add/<地址>`。它负责正确名称、节点刷新以及流量/到期横幅。
2. **配置页分流规则**：具名 HTTPS `.conf` 地址；一键导入使用 `shadowrocket://config/add/<地址>`。它不再复制节点，而以 Shadowrocket 原生 `PROXY` 作为默认出口，并用 `include-all-proxies=1` 与 `policy-regex-filter=.*` 请求各组枚举订阅节点，同时负责规则、手动切换及原生 `DIRECT` / `REJECT`。

二维码同样分成两步：第 1 张在 Shadowrocket 首页扫码，第 2 张在「配置」页右上角扫码。页面默认展示第 1 步，并在切换第 2 步前持续提示“两步都要导入”。复制地址时也必须粘贴到对应入口，不能交叉使用。

## 真机验收结果

2026-09-23 的实机回归先确认了两个对象各自能被导入，但也暴露出旧版 `.conf` 把节点再复制一份后，配置模式无法实际联网。本轮改为原生 `PROXY` 桥接；服务端回归确认两步组合应提供：

- 用户填写的订阅名称；
- 可刷新的订阅节点、跟随首页当前节点的 `PROXY` 出口，以及各组可单独选择的全部首页节点；
- 流量、容量与到期横幅；
- 完整规则；
- `♻️ 手动切换`及其他策略组；
- 可选的原生 `DIRECT`；
- 广告和 NSFW 默认使用的原生 `REJECT`；
- 策略组嵌套与各组默认选择；
- 配置模式默认通过 `PROXY` 使用首页当前节点，也可以在任一策略组中选择具体首页节点。

内置完整版、精简版、ACL4SSR 等第三方预设和允许的自定义远程配置均走同一转换链路。现代节点只保留在首页订阅，配置文件不再解释或重写它们的协议字段，因此不会产生第二份可能失真的节点定义；具体协议能否连通仍取决于 Shadowrocket 首页节点本身。

上游 `Subscription-Userinfo` 或完整 `STATUS=↑/↓/TOT/Expires` 会安全转换为用量响应头。首页节点订阅负责展示这些信息；配置页 `.conf` 负责原生策略语义。服务端同时向两条地址交付所需数据，但客户端不会把两个入口的 UI 与状态合并成同一个对象。

## 回归经过

- `site-v0.4.16` 的首页方案会生成两个条目，其中只有一个名称和横幅正确；
- `site-v0.4.19` 的首页方案导入了配置但没有节点；服务端多次返回 HTTP 200，仍不能证明客户端完成了节点导入；
- `site-v0.4.20` 将 provider 改为独立纯节点地址后，服务端确认主配置与节点响应均被成功请求，但首页仍没有节点；
- 完整 YAML 能稳定带来名称、节点和流量横幅，却不能让其中的 `DIRECT` / `REJECT` 成为 Shadowrocket 原生可选策略；
- 原生 `.conf` 从「配置」页导入后，规则、手动组和策略联动通过真机验证，但配置页本身不展示首页订阅横幅；
- 两条路径组合后，两边的已验证优点可以同时保留，且不再要求其中一个入口模拟另一个入口的语义。
- 后续真机回归发现旧 `.conf` 虽然显示完整策略组，但配置模式完全不能联网；全局模式选同一首页节点却正常，证明故障来自配置内复制节点与实际首页节点脱节，而不是机场节点失效。
- 当前 `.conf` 因此清空 `[Proxy]` 中的节点副本，`♻️ 手动切换`默认改为 `PROXY`，其他策略组在保留原有 `DIRECT` / `REJECT` 默认的同时增加 `PROXY` 作为代理出口。
- `site-v0.4.29` 真机确认配置模式已经能够联网，但各组只显示 `PROXY`，无法分别选择节点；节点可见性和代理出口必须分开处理。
- 当前输出在保留 `PROXY` 的同时，为所有策略组写入 `include-all-proxies=1`，未定义第三方筛选时补 `policy-regex-filter=.*`，请求从订阅动态枚举节点，而不是重新复制节点定义；实机尚未验证这一枚举结果。

这些结果说明“一条链接同时解决所有问题”不是服务端格式问题，而是 Shadowrocket 的对象模型边界。最终产品因此不再隐藏这个边界，而是把两个入口显式设计成一个两步流程。

## 自动化验证边界

测试会验证：

- 首页 `.yaml` 与配置页 `.conf` 都使用稳定名称，转换参数不会因嵌套 URL 丢失；
- 两个一键导入分别使用 `shadowrocket://add/` 与 `shadowrocket://config/add/`；
- 原生 `[Proxy]`、`[Proxy Group]`、`[Rule]` 均存在；
- `[Proxy]` 不含机场节点副本，手动组以 `PROXY` 开始；
- 每个策略组包含 `include-all-proxies=1` 和 `policy-regex-filter`，但不会把机场节点名称静态写回配置；
- 广告与 NSFW 组仍以 `REJECT` 开始，DIRECT 默认组仍以 `DIRECT` 开始；
- 首页地址透传用量元数据，第三方配置和旧链接兼容行为不回归。

自动化只能验证服务端交付内容，不能替代 Shadowrocket 的 UI 与真机解析。`PROXY` 桥接已经由 `site-v0.4.29` 真机确认；动态节点枚举仍需在空状态下依次导入首页和配置页，检查每个组是否列出首页节点并实际切换联网。诊断材料不得保存订阅查询串、token、节点密码、UUID 或设备标识。
